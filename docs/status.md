## 현재 구현 상태

- 첫 구현(합성 프로토타입)의 1~3단계는 구현되어 사용자가 직접 확인했다. 전체 프로토타입을 직접 플레이한 뒤 시험용 설정과 조작 세부 처리를 유지할지 바꿀지는 아직 정하지 않았다.
- 시스템 7개를 목록에 등록했다(game_design.md). 시스템별 상세 기획과 구현은 아직 시작하지 않았다. 합성 프로토타입은 시스템 목록과 별개로 구성한다(사용자 결정, 2026-11-07).
- 시스템별 상세 문서는 `docs/systems/` 아래에 만들며, 첫 시스템 승인 때 생성한다. 동기화 프로그램은 고정된 문서 4개만 대상으로 하고 현재 실행 중이 아니므로, `docs/systems/` 아래 시스템 파일은 사용자가 수동으로 평평하게 복사한다.
- Notion은 하루 작업 마지막에 갱신하며, 사용자 전달에 따르면 7번 페이지에 시스템별 기록을 둔다. Codex는 Notion 구조를 직접 확인하지 못했다.

## 미해결 문제

- 최종 보드 크기: 미정 (4×4는 시험용).
- 유닛(아이템) 구성과 종류별 단계 수: 종류는 3개로 확정(병사, 무기, 장비로 이해함 — 확인 필요), 단계 수와 이름은 미정.
- 소환 규칙: 방향은 확정(생성기가 확률에 따른 랜덤으로 판에 떨어뜨림). 확률, 생성 횟수 제한 여부, 생성 위치는 미정.
- 한 판의 목표와 종료 조건: 방향은 확정(퀘스트를 모두 완료하면 성공, 판이 가득 차면 실패). 퀘스트 개수·내용, 가득 찬 상태의 판정 시점은 미정 (3단계 종료는 시험용).
- 게임 흐름: 방향은 확정(위 기본 플레이 흐름). 세부는 미정.
- 승패 조건: 방향은 확정(위와 같음). 세부는 미정.
- 최종 제외 범위: 1주 기준 제외 범위는 위 "1주 제작 범위"로 확정.
- 화면 비율, 플랫폼: 미정.
- 데이터 테이블 구조: game_design.md의 "데이터 관리 원칙"에 미정 항목이 있다.
- 프로토타입 코드는 시험용 값을 코드에 직접 쓰고 있어 새 데이터 관리 원칙(테이블, 엑셀→CSV)과 다르다. 소급할지 시스템 구현 때 전환할지는 미정이다.
- Codex에서 Git 스테이징을 시도했으나 `index.lock` 생성 권한 오류로 실패했다. 사용자는 VS Code 터미널에서 스테이징과 첫 커밋을 완료했으며, Codex의 Git 쓰기 권한 문제는 해결되지 않았다. 이후 재검증하지 않았으므로 현재 상태는 미확인이다.
- 게임 기능 자동 테스트는 수행하지 않았고 결과도 없다. 1~3단계의 화면과 조작은 사용자의 직접 확인이다. 3단계끼리 합치는 안전 처리는 시작 배치로 만들 수 없어 직접 확인하지 못했다.
- 자동 커밋·푸시는 미설정이다. 승인된 자동 저장 규칙과 권한 검증이 없다.
- 동기화 프로그램은 사용자가 개발을 요청해 만들었다. 실행 방식은 사용자가 확인한 적이 없다. 아래 내용은 Codex가 코드·설정·로그를 읽어 점검한 보고 기준이며, 이번 점검에서 프로그램을 실행하지 않았다.
- `scripts/doc_sync.cmd start`로 수동 시작하며 숨김 PowerShell 프로세스가 백그라운드로 동작한다. 로그인 시 자동 시작은 설정되어 있지 않고 예약 작업도 없다. PID 파일이 없고 마지막 로그가 정상 중지 기록(2026-11-07 18:07:42)이므로 현재 실행 중이 아니다. 프로세스 목록 조회는 권한 오류로 확인하지 못했다.
- 시작 시 전체 대조, 원본 파일 변경 감지(700ms 모아 처리), 60초 주기 전체 대조를 한다.
- 복사 대상은 `AGENTS.md`, `docs/game_design.md`, `docs/status.md`, `docs/devlog.md` 네 개로 고정이며 `docs/systems/` 아래 새 파일은 포함되지 않는다.
- 원본에서 공유 폴더로만 복사한다. 공유 폴더에서 원본으로 쓰거나 원본을 지우는 동작이 없고, 공유 폴더에만 있는 파일과 원본이 없어진 파일의 기존 복사본은 지우지 않는다.
- Codex가 2026-11-07에 임시 폴더와 실제 설정으로 시험한 기록이 있다. 사용자의 직접 실행 확인 기록은 없고, 이번 점검에서는 실행하지 않았다.
- 사용자가 원하는 동작은 단방향 복사와 시스템 파일 자동 포함이다. 시스템 파일 자동 포함은 미구현이며, 개선은 별도 개발 요청으로 진행한다(대상 탐색, 하위 폴더 변경 감지, 공유 폴더 파일명 충돌 처리, 안내문 보완, PID 재사용 구분). 로그인 자동 시작은 사용자 PC 설정 변경이므로 필요하면 설명 후 승인을 받는다.
- 안내문(`docs/doc-sync.md`)과 코드는 서로 일치한다(Codex 보고). 이번 작업에서 동기화 프로그램 파일과 안내문을 수정·비활성화·삭제하지 않았다.
- Notion 메인 페이지 아래에 있던 출처 미확인 하위 페이지 6개(2026-11-07 한국시간 17:31에 사용자 계정의 Claude 연결로 만들어진 것으로 기록되었고, 사용자는 직접 만들지 않았다고 확인함)는 한국시간 17:45경 삭제된 상태로 확인했다. 삭제 주체는 확인하지 못했다.
- 커밋 전 변경 목록을 확인한다. 기존 AGENTS.md, main.tscn, scripts/main.gd 변경이 남아 있으며 이번 요청으로 네 문서도 변경했다. 커밋하지 않았다.
