# 게임 기획

## 목표와 제약

- 작업명: 나 혼자만 머지
- 약 1주(하루 최소 3시간 기준 약 21시간) 동안 제작하는 2D 게임이다. (사용자 결정, 2026-11-07. 기존 약 2주에서 변경)
- 넷마블네오 AI 인턴십 지원용 포트폴리오를 목적으로 하며, 게임 제작과 그 과정의 기록을 함께 담는다.
- 하루 작업 시간은 최소 3시간이다.
- Godot과 Codex로 구현하고, Claude Pro는 기획·명세·회고를 보조한다.
- 역할: 구현은 Codex가 맡는다. 최종 결정과 직접 플레이 검증은 사용자가 한다. 기획과 개발 기록은 Claude를 주 대화 상대로 진행한다.
- 스크립트 언어는 GDScript이다.

## 확정된 방향

- 콘셉트: 그림자 군단을 소재로 직접 제안하는 신규 미니게임이다. 기존 미니게임을 재현하는 것이 아니다.
- 핵심 행동: 보드에서 유닛을 드래그해 합치는 머지이다.

## 첫 구현(합성 프로토타입)

첫 구현의 목적은 임시 도형과 숫자로 합성 동작이 규칙대로 되는지 확인하는 것이다. 게임의 재미나 완성도를 판단하는 단계가 아니다.

### 조작 규칙 (사용자 승인)

1. 같은 단계 위에 놓으면 두 개가 합쳐져 놓은 칸에 상위 단계 하나가 생긴다.
2. 빈 칸에 놓으면 이동한다.
3. 다른 단계 위에 놓으면 원래 칸으로 돌아온다.
4. 보드 밖에 놓으면 원래 칸으로 돌아온다.

### 조작 세부 처리 (2·3단계 구현, 사용자가 직접 플레이로 확인함)

위 규칙에 없는 세부를 구현하면서 정한 처리이다. 첫 구현을 직접 플레이한 뒤 유지할지 바꿀지 시험용 설정과 함께 정한다.

- 놓는 칸은 마우스 포인터가 칸 사각형 안에 있는지로 판정한다.
- 칸과 칸 사이의 간격은 보드 밖으로 취급한다(규칙 4와 같이 원래 칸으로 돌아온다).
- 유닛을 집었다가 원래 칸에 다시 놓으면 변화가 없다.
- 3단계끼리 합치는 경우는 규칙이 없어 보드를 그대로 두고 원래 칸으로 돌아오는 임시 안전 처리를 한다. 시작 배치로는 이 상황을 만들 수 없어 직접 확인하지 못했다.
- 종료 후에는 유닛을 집거나 움직일 수 없고, 마지막 보드와 유닛은 화면에 그대로 남는다.

### 시험용 설정

아래 값은 첫 확인을 쉽게 하기 위해 고른 시험용 값이며 최종 설계가 아니다. 첫 구현을 사용자가 직접 플레이한 뒤 유지할지 바꿀지 정한다.

- 보드: 4×4
- 유닛 단계: 1~3. 임시 도형 안에 숫자로 표시한다.
- 종료: 3단계가 만들어지는 순간 종료한다. 화면에 "종료"라는 글자를 띄우고, 이후 유닛을 움직일 수 없게 한다.
- 시작 배치: 고정. 숫자는 유닛의 단계이고 `·`는 빈 칸이다.

```
1 1 · ·
· · 2 ·
· · · ·
1 · · 1
```

- 다시 시작 기능은 넣지 않는다. Godot 편집기에서 프로젝트를 다시 실행한다.

### 첫 구현에서 제외

- 소환
- 재화
- 전투
- 저장
- 최종 아트

## 전체 뼈대 (사용자 확정, 2026-11-07)

세부 규칙은 시스템별 기획에서 정한다. 아래는 전체 방향이다.

### 핵심 컨셉과 재미
- 컨셉: 퀘스트가 요구하는 상위 등급 아이템을 만들기 위해 생성기로 재료를 얻고, 계획적으로 합쳐 군단을 키우는 머지 퍼즐이다.
- 재미: 퍼즐 요소는 목표 등급을 만들 합성 경로를 계획하는 것이고, 그 결과로 군단이 커지는 쾌감을 느끼는 것이다.
- 그림자 군단의 병사가 메인 머지 대상이다. 무기와 장비도 함께 합치는 대상이다. 이 게임에는 군단만 나오고 주인공은 나오지 않는다.
- 아이템은 3종류이다(병사, 무기, 장비로 이해함 — 확인 필요). 종류별 단계 수는 미정이다.

### 기본 플레이 흐름
1. 화면 위쪽에서 이번 퀘스트의 목표 아이템을 확인한다.
2. 생성기를 눌러 재료를 판에 떨어뜨린다. 어떤 재료가 나오는지는 정해진 확률에 따른 랜덤이다.
3. 같은 종류에서 같은 단계끼리 드래그로 합쳐 단계를 올린다.
4. 목표 아이템이 만들어지면 퀘스트가 완료된다.
5. 모든 퀘스트를 완료하면 성공한다. 판이 가득 차면 실패한다.

### 본 게임 합성·이동 규칙 (사용자 확정, 2026-11-07)
- 합성은 같은 종류에서 같은 단계끼리만 가능하다. 종류가 다른 아이템은 단계가 같아도 합치지 않는다.
- 조작 규칙 3은 다음으로 확장한다: 다른 단계 또는 다른 종류 위에 놓으면 원래 칸으로 돌아온다.
- 조작 규칙 1, 2, 4는 그대로 유지한다.
- 위 규칙은 본 게임의 규칙이며, 위 "첫 구현" 섹션의 기록은 프로토타입이 구현한 규칙이므로 바꾸지 않는다.

### 데이터 관리 원칙 (사용자 확정, 2026-11-07)
- 게임 데이터는 코드에 직접 적지 않고 테이블로 관리한다. 테이블은 엑셀에서 작성해 CSV로 내보낸다.
- 생성기의 아이템 확률, 퀘스트 목표 등도 테이블 대상이다. 구체적인 테이블 목록과 형식은 시스템별 기획에서 정한다.
- 현재 프로토타입 코드의 시험용 값(보드 크기, 시작 배치, 칸 크기 등)은 코드에 직접 들어 있어 이 원칙과 다르다. 이를 소급해서 고칠지, 시스템 구현 때 전환할지는 미정이다.
- 데이터 테이블 구조를 별도 시스템으로 둘지 아이템 데이터 시스템에 포함할지는 미정이다.

### 화면·조작
- 조작은 마우스 드래그이다.
- 화면은 위쪽에 퀘스트 카드, 가운데에 보드, 한쪽에 생성기를 둔다. 자원 수치, 레벨, 잠긴 칸은 두지 않는다.
- 화면 비율과 플랫폼은 미정이다.

### 비주얼·사운드 방향
- 색감은 검정 바탕에 보라색 발광이다. 연출은 크게 중요하지 않으며 최소로 한다.
- 그림과 사운드는 AI(이미지 생성, 사운드 생성)를 활용해 만든다. 규칙이 정해지기 전에는 임시 도형으로 만들고, 마지막에 입힌다.
- 분위기와 색감만 참고하고 원작의 캐릭터 모양, 이름, 로고, 제목 글자는 쓰지 않는다. 생성 도구와 방법은 기록으로 남긴다.

### 레퍼런스
- 그림자 군단 컨셉 자료(웹툰 표지, 군단 컷, 게임 홍보 이미지): 검정과 보라색 발광, 폐허 배경, 크기로 위계를 보여 주는 군단의 느낌을 참고한다. 구도, 캐릭터, 이름, 로고는 가져오지 않는다.
- 머지 게임 UI 자료(스크린샷): 상단의 목표 아이템 카드 구조와 보드 중심 구성을 참고한다. 보상 코인, 인물 초상화, 에너지, 코인·보석, 잠긴 구역과 레벨, 건설, 아이템 그림은 가져오지 않는다.
- 자료 속 규칙은 이 게임의 규칙으로 자동 채택하지 않는다.

### 1주 제작 범위
- 포함: 드래그 합성(종류별), 생성기, 퀘스트, 성공·실패가 있는 한 판, 검정·보라 발광 색감, AI로 만든 이미지와 효과음 소량
- 제외: 전투, 재화·상점, 레벨·잠긴 칸, 에너지, 저장, 튜토리얼, 합성 연출, 종류 간 조합 합성, 최종 아트 수준의 완성도

## 미정 항목

- 최종 보드 크기: 미정 (4×4는 시험용)
- 유닛(아이템) 구성과 종류별 단계 수: 종류는 3개로 확정(병사, 무기, 장비로 이해함 — 확인 필요), 단계 수와 이름은 미정
- 소환 규칙: 방향은 확정(생성기가 확률에 따른 랜덤으로 판에 떨어뜨림). 확률, 생성 횟수 제한 여부, 생성 위치는 미정
- 한 판의 목표와 종료 조건: 방향은 확정(퀘스트를 모두 완료하면 성공, 판이 가득 차면 실패). 퀘스트 개수·내용, 가득 찬 상태의 판정 시점은 미정 (3단계 종료는 시험용)
- 게임 흐름: 방향은 확정(위 기본 플레이 흐름). 세부는 미정
- 승패 조건: 방향은 확정(위와 같음). 세부는 미정
- 최종 제외 범위: 1주 기준 제외 범위는 위 "1주 제작 범위"로 확정
- 화면 비율, 플랫폼: 미정
- 데이터 테이블 구조: 위 "데이터 관리 원칙"의 미정 항목 참고

## 시스템 문서

이 문서는 전체 기획 뼈대, 시스템 목록, 시스템별 상세 문서 링크를 관리한다. 시스템 상세 기획은 `docs/systems/` 아래 영문 파일명과 한글 제목을 사용하는 파일에 기록한다.

- 시스템 목록(사용자 확정, 2026-11-07). 우선순위는 구현 순서이며, 각 시스템의 상세 기획은 아직 시작하지 않았다.
  1. 아이템 데이터(종류와 단계)
  2. 합성 규칙 확장(같은 종류에서 같은 단계끼리, 조작 규칙 3 확장)
  3. 생성기(확률에 따른 랜덤으로 재료 드랍)
  4. 퀘스트(목표 제시와 완료 판정)
  5. 한 판 흐름(시작, 성공, 실패)
  6. 화면 UI(퀘스트 카드, 보드, 생성기)
  7. 색감·AI 이미지·사운드 적용
- 합성 프로토타입(구현 1~3단계)은 시스템 목록과 별개로 구성한다(사용자 결정, 2026-11-07). 시스템으로 등록하지 않으며 시스템 단계 값을 사용하지 않는다.
