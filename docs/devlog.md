# 개발 기록

## 초기 환경 구성

- **목표:** Godot 프로젝트 환경을 확인하고 초기 저장소를 준비했다.
- **AI에 맡긴 일:** Godot 버전과 프로젝트 설정 확인, 로컬 저장소 초기화 및 운영 문서 준비.
- **사용자의 결정과 이유:** 초기 커밋을 진행하고, 이후 문서화 작업에서 스테이징·커밋은 하지 않도록 지정했다.
- **변경 내용:** 초기 커밋 `bc0ebca` 생성. 초기 운영 문서 4개 작성.
- **검증 주체·방법·결과:** 에이전트가 실행 파일의 버전 출력 `4.7.2`와 프로젝트 설정을 확인했다. 사용자가 Godot 편집기에서 프로젝트 정상 실행·종료를 직접 확인했다. 이 확인은 자동 검사가 아니다.
- **남은 문제:** Codex의 Git 스테이징은 `index.lock` 생성 권한 오류로 실패했다. 사용자가 VS Code 터미널에서 스테이징과 첫 커밋을 완료했으며, Codex의 Git 쓰기 권한 문제는 미해결이다.

## 문서 커밋·저장소 게시·Notion 정리 준비

- **목표:** 운영 문서를 커밋하고 프로젝트를 GitHub 비공개 저장소에 게시하며, Notion 정리본 작성을 준비했다.
- **AI에 맡긴 일:** Claude가 공유 폴더의 문서 4개와 Notion 대상 페이지를 읽기 전용으로 확인하고, Notion 정리 초안과 원본 문서 갱신안을 제안했다. Claude가 커밋이나 게시를 실행한 것은 아니다.
- **사용자의 결정과 이유:**
  - 프로젝트 내부 Markdown을 원본으로, Notion을 검토·발표용 정리본으로 둔다. 새 기록은 원본 문서에 먼저 반영한다. 공유 폴더는 수동 갱신하는 복사본이며 자동 동기화되지 않는다.
  - Notion 정리본은 하위 페이지 없이 한 페이지의 본문 섹션 6개로 시작한다(Claude가 제안한 근거: 현재 정보량이 적음).
  - Notion 정리본에는 저장소 URL, 커밋 해시, 개인 절대 경로를 넣지 않는다.
  - 비공개 게시 설정 안내를 확인한 뒤 사용자가 직접 게시 버튼을 눌렀다.
  - Claude와 GitHub의 직접 연동은 선택적으로 보류한다. 이유: 현재 Filesystem으로 문서를 읽을 수 있으므로 중복 설정을 줄이고 게임 기획·구현을 먼저 진행하기 위해서다.
- **변경 내용:** 운영 문서 4개를 사용자가 GitHub Desktop에서 커밋했다. Godot 프로젝트를 사용자가 GitHub Desktop에서 GitHub 비공개 저장소에 게시했다.
- **검증 주체·방법·결과:** Claude가 Filesystem 도구로 공유 폴더 문서 4개 읽기에 성공했고, Notion 조회 도구로 대상 페이지 읽기에 성공했다(2026-11-07, 제목 확인, 당시 본문은 비어 있음). 이는 도구·커넥터 동작 확인이며 게임 기능 검증이 아니다. 커밋과 게시는 사용자가 수행했고 Claude는 직접 확인하지 않았다. 게임 기능 자동 테스트는 아직 수행하지 않았다.
- **남은 문제:** Codex의 Git 쓰기 오류는 재검증하지 않아 현재 상태가 미확인이다. Notion 정리본 작성은 아직 완료하지 않았다. 게임 기획의 미정 항목(콘셉트, 핵심 행동, 게임 흐름, 승패 조건, 제외 범위, 하루 작업 시간, 스크립트 언어)은 그대로다.

## Notion 정리본 1차 반영

- **목표:** Notion 'AI 게임 만들기' 페이지에 정리본 본문 섹션 6개를 작성했다.
- **AI에 맡긴 일:** Claude가 공유 폴더 문서 4개를 다시 읽고 대상 페이지에 기존 내용이 없음을 확인한 뒤, 사용자 승인에 따라 본문을 작성하고 재조회로 반영을 확인했다.
- **사용자의 결정과 이유:** 본문 작성을 승인했다. 하위 페이지는 만들지 않고, 저장소 URL·커밋 해시·개인 절대 경로는 정리본에서 생략한다.
- **변경 내용:** Notion 대상 페이지의 본문을 작성했다. 다른 Notion 페이지와 로컬 파일은 수정하지 않았다.
- **검증 주체·방법·결과:** Claude가 대상 페이지를 재조회해 섹션 6개가 반영된 것을 확인했다(2026-11-07). 화면 렌더링은 확인하지 못했다. 도구·커넥터 동작 확인이며 게임 기능 검증이 아니다.
- **남은 문제:** 이 페이지는 아래 항목의 게임 기획 확정 이전 문서를 기준으로 작성되어 확정 내용이 반영되어 있지 않다. 원본 문서와 자동 동기화되지 않으므로 수동 갱신이 필요하다.

## 첫 프로토타입 범위 확정

- **목표:** 합성 동작만 확인하는 첫 프로토타입의 범위를 정했다. 구현은 시작하지 않았다.
- **AI에 맡긴 일:** Claude가 결정 사항을 한 번에 하나씩 쉬운 말로 제시하고 선택지와 추천을 제안했다. 구현은 Codex가 맡을 예정이다.
- **사용자의 결정과 이유:**
  - 다른 대화에서 확정해 전달함(Claude는 직접 확인하지 못함): 작업명 "나 혼자만 머지", 그림자 군단 소재의 신규 미니게임, 보드에서 유닛을 드래그해 합치는 머지, 하루 최소 3시간 작업, 첫 구현의 조작 규칙 4개, 첫 구현은 임시 도형과 숫자로 합성 동작만 확인하고 소환·재화·전투·저장·최종 아트는 제외.
  - 이번 대화에서 확정: 스크립트 언어 GDScript, 시험용 보드 4×4(이유: 첫 확인용), 시험용 단계 1~3, 3단계가 만들어지는 순간 종료, 고정 시작 배치, 종료 시 "종료" 글자 표시와 조작 정지, 다시 시작 기능 제외.
  - 위 시험용 값은 최종 설계가 아니라 프로토타입 확인용이다. 이유를 따로 말하지 않은 항목은 이유를 기록하지 않았다.
- **변경 내용:** game_design.md, status.md, devlog.md를 갱신했다. 게임 구현 코드는 변경하지 않았다.
- **검증 주체·방법·결과:** 해당 없음. 합성 동작과 종료 동작은 구현 전이라 확인하지 않았고 자동 테스트도 수행하지 않았다.
- **남은 문제:** 미정 항목(최종 보드 크기, 유닛 구성과 최고 단계, 소환 규칙, 한 판의 목표와 종료 조건, 게임 흐름, 승패 조건, 최종 제외 범위)은 그대로다. 첫 구현 지시문 작성과 구현은 아직 하지 않았다. Codex의 Git 쓰기 오류는 재검증하지 않아 현재 상태가 미확인이다. Notion 정리본은 갱신이 필요하다.

## Notion 정리본 섹션별 페이지 분리

- **목표:** 한 페이지에 모든 섹션이 있어 가독성이 떨어지므로, 섹션별 페이지로 나누고 메인 페이지에 목록 표를 두었다.
- **AI에 맡긴 일:** Claude가 목록 표(데이터베이스)를 만들고, 섹션 6개를 표의 페이지로 작성한 뒤, 메인 페이지 본문을 목차(안내 박스와 표)로 정리했다.
- **사용자의 결정과 이유:**
  - 섹션별 페이지로 분리하고 메인 페이지에 목록 표를 둔다. 이유: 가독성. 이 결정으로 앞선 "하위 페이지 없이 시작한다"는 기록은 바뀌었다.
  - 앞으로 Notion은 섹션 페이지 기준으로 갱신한다.
  - 메인 페이지 아래의 출처 미확인 하위 페이지 6개는 사용자가 만든 것이 아니라고 확인했다.
- **변경 내용:** Notion 메인 페이지 본문을 목차로 바꿨고, 섹션 페이지 6개를 만들었다. 다른 Notion 페이지와 로컬 파일은 수정하지 않았다. 출처 미확인 하위 페이지 6개는 삭제하지 않고 보존했다.
- **검증 주체·방법·결과:** Claude가 섹션 페이지 6개를 읽어 내용이 들어간 것을 확인한 뒤 메인 본문을 정리했고, 정리 후 메인 페이지를 재조회해 반영을 확인했다(2026-11-07). Notion 변경 기록으로 출처 미확인 페이지가 2026-11-07 한국시간 17:31에 사용자 계정의 Claude 연결로 만들어진 것으로 기록되어 있음을 확인했으나 생성 주체는 확인하지 못했다. 화면 렌더링은 확인하지 못했다. 도구·커넥터 동작 확인이며 게임 기능 검증이 아니다.
- **남은 문제:** 출처 미확인 하위 페이지 6개의 정리는 사용자가 한다. 이번 1단계 기록은 아직 Notion에 반영하지 않았다.

## 구현 1단계: 보드와 유닛 표시

- **목표:** 4×4 보드와 고정 시작 배치의 유닛을 화면에 표시한다. 구현은 3단계로 나눠 진행한다(1단계 보드와 유닛 표시, 2단계 드래그 이동과 합성, 3단계 종료 표시).
- **AI에 맡긴 일:** Claude가 1단계 지시문을 작성했고, Codex가 구현했다. Codex 보고 기준이며 Claude는 코드를 읽지 못했다.
- **사용자의 결정과 이유:**
  - 구현 단계를 5단계에서 3단계로 줄인다.
  - 구현 지시에서는 Codex가 코드만 수정하고, 문서 갱신은 별도 지시로 한다. 각 구현 단계의 결과를 확인한 뒤 Claude가 갱신안을 제안하고 사용자가 승인하면 반영한다. 이유(Claude 제안): 기록의 사실 여부를 사용자가 먼저 검토할 수 있다.
- **변경 내용:** Codex 보고 기준으로 `main.tscn`의 메인 `Node2D`에 스크립트를 연결했고(+3), 새 파일 `scripts/main.gd`를 만들었다(+75). `main.gd`는 보드와 유닛을 그리고, `board_state`에서 칸의 단계를 읽고 바꾸는 함수를 제공한다. 칸 112px, 칸 간격 8px, 유닛 원 반지름 34px, 단계별 원 색, 어두운 배경과 칸 테두리 색은 임시 값이다. 문서, `project.godot`, 게임 규칙은 바꾸지 않았다.
- **검증 주체·방법·결과:** 에이전트(Codex)가 `main.tscn` 변경분에 `git diff --check`를 실행했다. 서식 검사이며 동작 검증이 아니다. Codex는 Godot 실행과 게임 플레이를 하지 않았다. 사용자가 Godot 편집기에서 직접 실행해 4×4 칸, 고정 시작 배치와 일치하는 유닛 5개(1단계 4개, 2단계 1개), 단계 숫자가 보임을 확인했다(스크린샷 기준). 이 확인은 자동 검사가 아니다. 조작이 되지 않는 것은 1단계 범위 밖이라 의도한 상태이다. 출력 창의 경고·오류 여부는 확인하지 못했다. 게임 기능 자동 테스트는 수행하지 않았다.
- **남은 문제:** 2단계와 3단계는 시작하지 않았다. 출력 창 오류 여부는 미확인이다. Codex가 작업 전부터 저장소에 자동화 작업 파일과 문서 변경이 남아 있다고 보고했으며 내용은 확인하지 못했다. 커밋 전 변경 목록을 확인한다. Codex는 이번 변경을 커밋하지 않았고 사용자의 커밋 여부는 기록하지 않았다. Codex의 Git 쓰기 오류는 재검증하지 않아 현재 상태가 미확인이다. 미정 항목은 그대로다.
