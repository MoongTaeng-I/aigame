  - 접촉에 의한 밀어내기와 공격에 의한 넉백을 별개로 구분한다.
  - 적도 맵 경계에서 막힌다. 밀리는 과정에서도 맵 밖으로 나가지 않는다.
  - 동시 존재 수에 상한을 두고, 상한을 넘기게 되는 수량은 생성하지 않는다.
  - 화면 밖에 연속 n초 머문 적은 플레이어 주변으로 재배치한다. 재배치는 신규 생성과 다른 기능이며, 기존 개체의 위치만 옮기므로 전체 수가 늘지 않고 상한의 남은 자리를 쓰지 않는다. 상한 도달 상태에서도 가능하다.
  - 재배치 위치 규칙은 신규 생성과 동일하며 위치 계산 기능을 공유한다. 화면에 다시 들어오면 체류 시간을 0으로 초기화한다. 체력과 전투 상태는 유지한다.
  - 밀어내기는 매 프레임 한 번만 처리하고 완전 분리를 보장하지 않는다. 적이 몰릴 때 일부 겹침을 초기 구현에서 허용하고, 실제 테스트에서 성능과 밀집 상태를 확인한다.
  - 생성 가능한 방향이 하나도 없으면 그 주기에는 생성하지 않고 넘어간다. 현재 맵 크기에서는 발생하지 않지만 맵 크기를 바꿀 경우를 대비한 안전장치다.
  - `spawn.csv`의 시간대가 겹치면 겹친 행을 모두 적용해 여러 적 종류가 동시에 나오게 한다. 어떤 행도 해당하지 않는 시각에는 생성하지 않는다. 둘 다 오류로 처리하지 않는다. 겹침은 여러 종류를 동시에 내보내는 데 쓰고, 빈 구간은 소강 상태로 쓴다.
  - 생성 규칙은 `spawn.csv` 한 곳에서만 관리하고, 보스 등장 시점과 적 강화 배율은 시스템 8의 `stage_timeline`에 둔다. 같은 규칙을 두 테이블에 중복하지 않는다.
  - 최종 보스 등장 후 일반 생성 중단은 시스템 8이 조건을 판정해 신호를 보내고 시스템 2가 신규 생성을 멈추는 구조로 한다. 조건 판정과 생성 동작을 중복 구현하지 않는다.
  - CSV 공통 자료형에 `Enum`을 추가한다. 엑셀과 CSV에는 식별값을 문자열로 적고 읽을 때 검사해 코드 내부 Enum으로 변환한다. 허용값에 없으면 CSV 오류로 처리한다. 이유: CSV는 사람이 읽고 쓰는 원본이라 식별값이 명확해야 하고, 코드는 오타에 안전해야 한다.
  - 초기 콘텐츠는 적 2종이며 최종 개수가 아니다. 기존 기능으로 표현되는 적은 테이블 행 추가로 대응하고, 새 행동이 필요하면 추가 시스템 구현으로 구분한다.
  - A단계 시작값을 정했다. 최종 밸런스가 아니며 사용자가 엑셀에서 조정한다. `Max_alive` 200은 테스트 상한이지 성능이 검증된 수가 아니다.
- **변경 내용:** `docs/systems/02_enemy_spawn_and_movement.md`를 새로 만들었다. `game_design.md`의 데이터 관리 원칙에 `Enum` 자료형을 추가하고, 시스템 목록 2번에 파일 링크와 단계를 넣었으며, 미정 항목의 적 종류와 경계 부근 생성 위치를 정리했다. `docs/systems/01_player_and_map.md`의 테이블 항목에 `player.csv` 열 추가 예정을 적었다. `status.md`를 갱신했다. 코드는 바꾸지 않았다.

## [시스템 2 적 생성과 이동] 구현·테스트·완료

- **목표:** 승인된 규칙 20개를 A단계 범위에서 구현하고 플레이로 검증한다.
- **AI에 맡긴 일:** 생성 위치 계산, 추적 이동, 무게 기반 밀어내기, 화면 밖 체류 개체 재배치, 동시 생존 상한, Enum 열 검사, 테이블 연결.
- **사용자의 결정과 이유:** 적도 플레이어를 밀어내게 했다. 적이 벽처럼 느껴지는 것이 뱀서라이크의 압박감에 맞기 때문이다. 끼임 보정은 넣지 않았다. 맵 벽을 등지고 둘러싸여 못 움직이는 상황을 플레이어의 실수로 남기기 위해서다. 화면 밖 적을 삭제하지 않고 재배치하기로 했다. 생성 상한을 소모하지 않고 적 밀도를 일정하게 유지할 수 있어서다.
- **변경 내용:** `enemy_manager.gd`에 생성·재배치·밀어내기·상한을 넣었다. 생성 위치 계산은 신규 생성과 재배치가 같은 함수를 공유한다. 두 경로가 어긋나지 않게 하려는 목적이다. 밀어내기는 매 물리 프레임 한 번만 돌고, 공간 격자로 인접 개체만 비교한다. 적은 풀에서 재사용한다. `csv_data_store.gd`에 Enum 허용값 검사를 추가했다. 테이블 4종을 연결했다.
- **검증 주체·방법·결과:** 사용자가 실행 파일로 20개 항목을 직접 확인했고 전부 통과했다. 생성 위치 3개, 밀어내기 4개, 재배치 5개, 상한 2개, 테이블 반영 4개, 성능과 출력 2개다. 적 200마리를 1분 유지했을 때 프레임 저하가 없었다. 테이블 값을 바꾸면 즉시 반영되고, Enum에 없는 값을 넣으면 멈추고 화면에 오류가 떴으며 한글이 깨지지 않았다.
- **남은 문제:** 경과 시각을 `enemy_manager.gd`가 임시로 들고 있다. 시스템 8에서 옮긴다. B단계 콘텐츠가 남아 있다.
